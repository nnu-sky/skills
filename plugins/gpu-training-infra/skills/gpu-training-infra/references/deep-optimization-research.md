# 深度计算优化研究

## 目标

研究现有模型、算法或计算程序的效率改进机会。通过理解数学结构、算法、数据表示、依赖和实际执行，探索更高效的计算方式。不限业务、硬件、技术方案，不要求每次必须提出新算子或新算法。深度研究可与常规优化并行。

## 理解计算

从真实工作负载、输入、输出、状态和执行周期入手，理解数学目的、关键依赖、数据结构与各阶段关系，分析计算、存储、访存、通信、同步和调度开销。不能只凭热点代码认为计算方式本身已经合理。

复用项目源码、论文、运行日志和性能工具；仅在需要时深入数学推导、算法复杂度、编译结果或底层执行。

## 多层次寻找机会

- **数学与数值**：代数替代、固定深度计算、递推消除、近似和精度分配。
- **算法与状态**：复杂度、增量更新、搜索、冗余消除和历史状态复用。
- **表示与存储**：稀疏性、布局、索引、压缩、中间结果及数据组织。
- **算子与硬件**：向量化、归约、融合、局部存储、并行划分、异步流水线。
- **编译与系统**：图编译、自动调优、代码生成、内存管理、通信及资源调度。
- **完整流程**：跨阶段计算消除、数据移动、长期周期费用和流程重组。

以上仅为开放式研究视角，不是必须完成的技术清单。支持跨层组合和未列出的方案。

## 相关工作与方案

针对发现的计算结构，调查同领域成熟方案、其他领域的相似计算模式、数学和算法替代、编译器与库以及硬件实现。理解已有方法的作用机制和适用范围，而不是照抄某篇论文的方法表。

根据计算依据提出实质不同的候选，允许成熟成果复用、方法组合、已有机制改进或独立新方案。方案应该解释预计省掉什么工作或资源成本，而不是只列技术名词。

## 实现与研究迭代

根据收益潜力、依据和实验成本，选择理论推导、局部算子、微基准、短执行片段或代表性应用原型；有价值时深入实现，并逐步验证实际工作负载收益。不固定候选数或研究轮数。

实验反馈既用于保留或回退改动，也用于更新对原始计算的理解。若优化收益不明显、局部加速不能转化为整体加速，或新的瓶颈出现，应结合新证据重新审视假设与计算依赖，必要时修改优化对象、调整数据或执行方式、探索不同层次的替代机制；不局限于继续尝试最初列出的候选。

每次有效改动后重新观察实际执行行为，允许继续完善已采用方案，也允许推翻先前路线。不能因为完成一次代码修改、获得局部收益或初步短测就默认结束深度研究；当用户目标已经达到，或后续机会缺乏合理依据、预计收益不值得投入时，交付当前最佳成果。

常规正确性检查随改动风险和任务容差而定；不强制复杂数值证明、失败机制专项审查、多随机种子或完整训练。保持局部和端到端收益口径一致。

## 按需并行与集成

多个互相独立且值得并行的任务，可利用可用智能体或独立会话同时开展。需要并行改动代码时，优先建立不同 Git 工作树与分支，各自使用明确基准版本和隔离的实验输出。工作树不隔离共享 GPU 和外部路径，正式计时需协调设备。主代理比较并整合有效改动；不固定并行数量，简单任务不强制并行。

## 成果

工程任务重视时间、吞吐、资源与实用性；研究任务进一步提炼机制和适用条件；论文任务再评估成熟强基线、相关工作、新颖性与证据。记录重要假设、有效实现和后续候选，复用项目已有研究日志。可以积累可迁移计算机制，但不要求每项改进都具有普适性。
