# 日常运维参考

只读取与当前任务相关的小节。所有示例都使用 SSH 别名，不写公网或内网地址。

## 远程命令与环境

身份、工作目录或环境尚不明确且影响当前任务时再查询：

```bash
ssh <别名> 'hostname; id -un; pwd; uptime'
ssh <别名> 'command -v python3; python3 --version; command -v conda || true'
```

远程命令包含变量、通配符或重定向时，确保它们在预期的一端展开。路径必须显式并正确引用；不要把本地未解析的环境变量当成远程路径。

## GPU、进程与训练

启动计算任务前查看相关 GPU、进程和会话；单纯查询日志不执行这些检查：

```bash
scripts/lab-server-status.sh gpu <别名>
scripts/lab-server-status.sh jobs <别名>
scripts/lab-server-status.sh sessions <别名>
```

终止任务前确认 PID 或调度作业的所有者、完整命令、工作目录、运行时长和日志。Slurm 任务优先使用 `scancel <job-id>`，不要直接杀 worker PID。

长任务优先遵循服务器现有调度方式。没有调度器时才使用项目已有的 tmux、screen、nohup 或用户服务约定。启动时记录：服务器别名、会话或作业名、工作目录、环境、GPU、命令、日志路径和 PID/作业号。启动后复查进程与日志，不能只凭命令退出码宣布成功。

## 日志

先读取有界日志：

```bash
ssh <别名> 'tail -n 200 <明确日志路径>'
ssh <别名> 'journalctl --user -u <用户服务> -n 200 --no-pager'
```

不要默认读取包含凭据的环境文件、完整 shell 历史或认证日志。需要系统级日志或服务操作时先确认影响范围，再按管理操作处理权限。

## 文件传输

小文件可使用 `scp`；目录、断点续传或增量同步优先使用 `rsync`。可能覆盖或删除时先 dry-run：

```bash
rsync -anvi --itemize-changes <本地源>/ <别名>:<远程目标>/
```

审核预览后再移除 `-n`。除非用户明确要求删除目标端多余文件，不添加 `--delete`。关键数据传输后比较大小或校验和。

## Git 仓库

先读取状态：

```bash
scripts/lab-server-status.sh repo <别名> <远程仓库路径>
```

诊断时优先 fetch，而不是直接 pull。存在本地修改时，不擅自 stash、丢弃、合并、变基或覆盖。hard reset、clean 和强推必须由用户明确选择。

## 磁盘与清理

先确定文件系统、inode 和大目录：

```bash
scripts/lab-server-status.sh disk <别名>
ssh <别名> 'du -xhd1 <明确路径> 2>/dev/null | sort -h | tail -n 30'
```

缓存、checkpoint、环境、数据集、日志和临时目录即使很大也不能自动删除。列出候选、大小和恢复代价，等待用户批准明确路径。

## 管理操作

管理员账号只用于确实需要 sudo、用户管理、权限、服务或系统配置的任务。先用普通账号完成诊断；需要提升权限时无需再次询问，优先使用管理 SSH 别名，其次使用 `sudo -n`。两者都不可用时，报告目标服务器缺少免密管理入口，不通过聊天索取或回显密码。

跨账号读取使用 `sudo -n -u <用户>` 执行实际命令，不修改目标文件权限来绕过访问限制。项目目录和 Python/Conda 环境以目标项目现有配置为准，不把一台服务器的路径套用到其他服务器，也不修改共享环境来满足个人任务。

## 连接故障

只有实际 SSH 错误指向别名、地址、端口或密钥配置时，才使用 `ssh -G <别名>` 检查当前机器的生效配置；不回显完整配置。认证失败、目录无权限或一次超时不等于地址迁移。主机指纹变化须核实目标身份，不关闭校验或直接清除旧记录。
