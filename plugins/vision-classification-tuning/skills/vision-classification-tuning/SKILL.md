# 视觉训练配方优化

## 目标与边界

先读项目代码，再结合成熟训练经验主动发现候选。技能负责回答“当前项目还可以从哪些方向提升、先测试什么、怎样低成本验证”，而不是等待用户逐项点名方法。

以项目原有主要指标为目标，在保持网络结构和任务定义不变的前提下优化训练配方。

具体项目的名称、路径、固定参数和实验结果只写入项目记录，不写入本技能。

## 核心流程

1. 读取项目的 `AGENTS.md`、目标、计划、决策记录、训练入口、配置、损失、数据管线、评价代码和已有日志。只读分析不创建文件。
2. 读取[代码与训练配方审查](references/objective-and-state-audit.md)，用简短摘要说明当前模型、数据、损失、优化器、学习率、调度、增强、正则化、按步状态、训练预算和主要指标。
3. 读取[候选发现与排序](references/candidate-ranking.md)，主动扫描通用候选池和项目特有参数；不要只检查用户提到的方法。
4. 排除与当前目标、标签、视图或状态更新不兼容的候选，在内部排序后向用户展示三到五个最值得测试的方向，并明确推荐一个首选。
5. 根据用户授权决定下一步：
   - 用户只要求分析、建议或审查：报告候选后停止，不修改代码或启动训练。
   - 用户要求测试首选或授权自主短测：自动实现并运行一个首选候选，不在候选选择处再次停下。
   - 用户指定候选：直接验证该候选；若数学语义不成立，说明原因并停止。
   - 用户明确授权多个对照：最多运行两个候选，不自动展开组合网格。
6. 运行实验时读取[实验设计与决策](references/experiment-design-and-acceptance.md)，优先复用已有锚点，只改变候选声明的因素，并先打通训练、保存、加载和正式评价链路。
7. 短测结束后自动淘汰明显失败的候选；明显有希望、差异很小或需要完整训练时报告证据与成本。未经明确授权，不从短测自动扩大到完整长训练、多卡训练或多个组合。
8. 用项目原有主要指标判断，不用训练损失、固定步吞吐或外部论文结果替代项目评价。记录收益、成本、负结果和适用边界。

## 按需读取

- 批量、学习率、预热、调度或优化器：读取[批量、优化器与调度](references/batch-optimizer-and-schedules.md)。
- 标签平滑、增强、MixUp、CutMix 或正则化：读取[增强与正则化](references/augmentation-and-regularization.md)。
- EMA 或 SWA：读取[模型权重平均](references/model-weight-averaging.md)。
- CIFAR 与 ImageNet 迁移：读取[数据集边界](references/cifar-and-imagenet-boundaries.md)。
- 需要外部依据：读取[一手证据](references/primary-evidence.md)，公开结果只用于形成候选。

## 候选输出

先给出当前配方摘要和最主要的改进空间，再为每个候选说明：

```text
候选名称：
代码依据与项目适配理由：
建议改动：
预期作用：
已有证据：当前项目／相近实现／通用先验
成本与风险：
与其他候选的组合或冲突：
推荐级别：首选／备选／条件候选
验证方式：
```

运行后使用“初步验证、项目验证、已拒绝、暂时无法判断”描述状态。未经实验验证，不把候选写成默认有效方法。

## 强制原则

- 主动发现候选，但不自动把候选全部加入训练。
- 当前项目代码和证据优先，通用经验用于补全候选池而不是替代实验。
- 软化损失目标与硬标签状态更新可以分开，但两条路径必须明确并分别验证。
- 批量变化时把批量、学习率、预热、调度和按步状态视为联合配方。
- 短测用于判断是否值得继续，不能单独证明最终有效。
- 相同依据下优先低成本、易归因、与现有配方重叠较少的方法。
