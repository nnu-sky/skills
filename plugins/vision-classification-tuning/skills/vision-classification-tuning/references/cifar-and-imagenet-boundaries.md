# CIFAR 与 ImageNet 的迁移边界

具体项目的批量、学习率、预热、增强和正则化结果留在项目报告中。跨数据集只迁移判断方法，不迁移固定参数或收益数字。

## CIFAR-10 与 CIFAR-100

- 两者图像尺寸相同，但类别数、类间细粒度和过拟合行为不同。
- 同一个标签平滑、增强强度或批量配方可能方向相反，必须按当前项目指标比较。
- 小图像上的随机擦除、裁剪和 CutMix 可能更容易破坏主体，应从温和强度开始。
- 逐 PNG 数据集的数据加载优化属于 `gpu-training-infra`，不要与涨点结论混在一起。

## ImageNet-100 与 ImageNet-1K

- 明确类别子集、类别编号映射、输入尺寸和预处理方式。
- 公开配方多基于 ResNet-50 和更长训练，不可直接当作 ResNet34 的结论。
- JPEG 解码和增强可能成为输入瓶颈；先由 `gpu-training-infra` 判断数据等待，再决定是否测试新数据后端。
- 强增强、EMA 和较大批量经常与更长训练预算绑定，迁移时把整套相互作用说明清楚。

## 迁移原则

迁移的是“优先尝试什么”和“哪些组合值得注意”，不是具体批量、学习率、增强强度或 EMA 衰减率。每到一个新项目都先读取其现有配置和日志，再筛选少量最相关候选。
