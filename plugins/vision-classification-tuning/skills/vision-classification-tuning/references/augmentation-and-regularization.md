# 增强与正则化

## 单项优先

把下列方法纳入内部候选池，再由主流程与其他优化方向共同筛选三到五个用户可见候选；不要把所有方法一次性打开。自主短测默认只运行推荐的一个候选；仅当用户明确要求比较多个时才最多运行两个。先逐项测试，再组合已稳定获益且机制不过度重叠的方法：

- 标签平滑：从较小强度开始，计算开销可忽略，但会改变置信度和训练损失下限。
- TrivialAugment Wide：无需搜索固定强度，适合作为低维护候选；仍需本项目实测。
- RandAugment：操作数和强度依赖数据集与模型，不使用跨数据集固定值。
- AutoAugment：复用成熟库的预定义策略，不在普通项目中重新搜索策略。
- 随机擦除：从低概率开始，避免用过强遮挡掩盖小图像主体。
- MixUp：混合图像和软标签；先单独测试较温和强度。
- CutMix：粘贴图像区域并按面积混合标签；先与 MixUp 分开测试。
- 指数移动平均：不改变推理结构，但增加训练状态和检查点复杂度，放在最终候选阶段；具体衰减、预热和批归一化策略按主文件路由读取“模型权重平均”。

标签平滑、MixUp 和 CutMix 只用于明确支持软目标的损失分支。若项目同时使用硬类别掩码、正负样本对、原型归属、Sinkhorn 分配或同图多视图约束，先把“损失目标”和“状态更新标签”分开：允许只平滑兼容的判别损失，同时让原型等状态继续使用硬标签；需要改变配对、分配或状态更新语义时，才将其视为方法变体。

默认排序不是跨项目结论：批量变化先处理学习率和预热；明显过拟合时优先标签平滑或一种轻量增强；软标签候选从标签平滑、MixUp、CutMix 中先选一种；后期检查点波动或最终权重不稳定时再考虑 EMA。当前项目证据优先于通用顺序，但只能作为该项目的先验。

## 组合边界

在软目标兼容的前提下，标签平滑、MixUp 和 CutMix 都会软化监督目标，不默认叠加。RandAugment、AutoAugment、TrivialAugment Wide 和随机擦除也可能产生重叠扰动；只有单项稳定获益后才做小规模组合。

强增强往往在更长训练中才表现出来。短跑可以淘汰数值失败或极端退化，但不能把慢热写成永久负结论。

## 不属于本技能首轮范围

- 新增注意力、额外头部或其他网络模块；
- 随机深度等会改变前向路径的方法；
- 神经架构搜索、模型分片、卷积手工拆分；
- 手写 CUDA 或 Triton 算子；
- 只为解决显存不足而引入的梯度累积或激活检查点。

这些方法可能有价值，但它们改变了问题边界，不能和“不增加模块的训练配方”放在同一个对照中。

## 项目证据的使用方式

项目局部结果只作为该项目下一轮排序依据。把具体参数、收益和负结果写入项目报告；通用技能只保留选择机制，不把单个数据集或模型的结论迁移为默认。
