# 批量、优化器与调度

## 选择批量

1. 接收 `gpu-training-infra` 输出的当前批量和吞吐拐点批量，不重新追求最大批量。
2. 读取两者的吞吐、预计墙钟、显存、尾批、每周期更新次数和回本训练次数。
3. 分别保留“当前批量原配方”和“拐点批量联合配方”，让用户根据预计收益决定是否测试后者。
4. 多卡时使用全局批量：`每卡批量 × GPU 数量 × 梯度累积步数`。

固定步吞吐只是成本预测。采用新批量前，至少用真实数据加载、尾批、周期重排和项目原有周期性工作跑若干完整周期，核对实际每周期墙钟；编译冷启动、第二种尾批形状、保存、评价和数据进程行为都可能使完整训练偏离固定步估算。最终同时报告固定步估算与完整训练实测，不用前者覆盖后者。

性能技能只负责给出批量候选和成本证据；本技能不假设学习率必须按某个公式改变，而是建立少量可解释候选并用验证结果决定是否采用。

批量增大通常会减少每轮参数更新次数，并改变批归一化统计和梯度噪声。因此必须重新验证学习率、预热、权重衰减和总训练预算。更大批量不是免费加速，也不保证更高准确率。

同时检查所有按步更新状态。设旧、新每周期成功更新次数为 `U_old`、`U_new`，旧动量为 `β_old`；若要近似保持按周期的指数衰减时间尺度，可把下式作为待验证起点：

```text
β_new = β_old ^ (U_old / U_new)
```

该换算适用于按成功更新推进的指数状态，不自动适用于队列、记忆库或依赖批内分配的算法。队列还要检查按样本计的覆盖窗口，原型和聚类还要检查批内统计变化。保持旧动量作为归因锚点，换算值作为联合候选，不预设换算后一定保持最终指标。

## 学习率与预热

- 设批量倍率为 `r = 新批量 / 原批量`，原学习率为 `lr`。普通模式按顺序考虑：保持 `lr`、平方根候选 `lr × sqrt(r)`、线性候选 `lr × r`。
- 不机械运行三个候选。先保留原学习率锚点；平方根缩放通常作为较保守的主要候选；线性缩放只在更大批量、欠更新证据或相近成熟配方支持时加入。
- 对大批量或高初始学习率优先测试短预热；小批量、低学习率未必需要预热。
- 在少量候选中比较“保守学习率”和“按批量缩放学习率”，不要进行无边界网格搜索。
- 前期先检查第 1 轮和前若干轮是否稳定；完整收敛结论仍需跑完调度。

若选择 `W` 个周期预热并接余弦退火，应使用一条连续曲线：前 `W` 个周期从较小学习率升至目标学习率，余下周期再从该目标值按余弦下降。`W` 由批量倍率、目标学习率、总预算和初期稳定性决定，不固定为某个数。余弦阶段使用剩余的“总周期−W”，不能在交界处重复推进调度器。尽量按成功的优化器更新次数推进；混合精度溢出跳过参数更新时，学习率也不应独自前进。

快速筛选时最多保留：原批量原配方、拐点批量原学习率与原状态、拐点批量主要缩放学习率＋必要预热＋状态时间尺度候选。用户认为预计收益不值得时，停止批量调优并保持原配方。

## 优化器和调度顺序

以项目原有优化器为锚点。对标准 ResNet 分类，带动量的随机梯度下降通常是稳健起点。按以下顺序试验：

1. 固定优化器，联合确定批量、学习率和预热；
2. 在相同总轮数下比较阶梯衰减与余弦退火；
3. 再测试权重衰减的少量倍数；
4. 最后测试 Nesterov 或指数移动平均等附加项。

不要因公开项目使用 AdamW、LAMB 或超长训练就整包迁移。优化器变化会同时改变学习率、权重衰减和预热的合适范围。

## 报告口径

同时报告：

- 每秒样本数与每轮墙钟时间；
- 每轮更新次数与总更新次数；
- 最后若干轮验证均值和最佳验证点；
- 达到预设主要指标阈值所需时间；
- 项目已有的重复结果及其差异（如有）。
