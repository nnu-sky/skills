# 代码与训练配方审查

不要根据模型或数据集名称猜测配方。沿实际代码、配置和日志形成一份简洁的当前状态摘要。

## 必查代码

- 训练入口、默认参数和实际启动脚本；
- 模型输出及初始化、是否使用预训练；
- 损失函数如何消费标签、表征、距离或相似度；
- 数据划分、归一化、基础增强和多视图关系；
- 优化器、批量、学习率、预热、调度、权重衰减和总训练预算；
- 验证、检查点选择、最终评价指标和已有日志；
- 原型、教师、目标网络、队列、记忆库、EMA、优化器动量和调度计数等按步状态。

## 配方缺口摘要

完成读取后明确回答：

1. 当前已经使用了哪些主流训练技巧？
2. 哪些主流方向尚未使用或实现不完整？
3. 日志更像初期不稳、欠拟合、过拟合、后期波动，还是尚无足够证据？
4. 哪些参数是普通训练配方，哪些是当前方法特有参数？
5. 哪些候选能低成本接入，哪些会改变任务或损失语义？

没有完整日志时，允许根据代码形成候选，但必须把依据标为“代码推断”，不能假装已经观察到过拟合或收敛问题。

## 标签与状态分离

先区分监督损失目标和状态更新标签：

- 被软化的损失分支必须正确消费软目标；
- 原型、队列、教师或分配状态可以继续使用独立硬标签；
- 同一个标签张量承担不同语义时，先拆清路径再测试；
- 需要改变配对、分配或状态更新定义的候选应标为方法变体，不作为普通配方开关。

## 正确性问题

发现标签映射、归一化、学习率顺序、评价、保存加载或非法数值错误时先修复。正确性修复不是涨点候选，修复后的配置才是比较锚点。
