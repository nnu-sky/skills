# 论文匿名代码发布

交付可供审稿人访问和运行的最小代码包。区分“本地准备完成”“私有源已上传”“匿名链接可用”“公开下载已验证”；只有最后两项完成，才称匿名发布完成。

## 确定范围与维护位置

- 复用项目已有发布目录、导出工具和发布记录。不要将研究目录整体上传，也不要从历史对话推定本次允许发布所有文件。
- 根据用户要求选核心实现、依赖、运行说明、最小验证入口和必要数据。说明哪些结果可复现、哪些只是论文表格快照，避免把精简发布写成完整实验复现。
- 权重可选。若发布原始/修改方法的一对模型，核对数据划分、训练设置与检查点选择是否匹配；存在有意差异就在说明中写明。不要为了发布包新增训练。
- 账号、源仓库位置、具体论文链接和到期日保存在项目本地发布记录中，不写入本 Skill 或通用模板，也不要随匿名包发布维护记录。

## 准备干净的发布包

1. 按选定文件清单复制到独立目录，保留必要许可证和公开上游归属。排除原 `.git`、日志、缓存、个人配置、数据集本体和未经选定的结果。
2. 用相对路径或命令参数替代机器路径。检查源文件、文档、文件名、链接及需要发布的图像/PDF元数据中的姓名、账号、邮箱、绝对路径和凭据。搜索只报告文件及问题类别，不把疑似密钥打印到输出。通用扫描和平台关键词屏蔽都不能单独证明匿名性。
3. 留意会指回作者的相对 Markdown 链接、徽章、外链、图片地址和 Git 信息。保留合法第三方署名，不将其误当作者身份全部删除。
4. 压缩包使用相对条目；排除符号链接指向的外部内容。再次打包时也排除新建的 `.git`。不要包含用户目录名或本地归档元数据。

### 若包含权重

- 复用现有模型结构和导出器，优先发布纯参数格式（例如 safetensors）。按模型需要保留参数和推理所需缓冲区，去除优化器、随机数状态、任意对象和个人配置；训练任务所需类别统计是否保留要明确说明。
- 不对来源不明的检查点执行任意 pickle 反序列化。旧版可信检查点需要特殊加载时，将处理限制在原可信环境；不要把关闭安全加载变成通用默认。
- 提供最小公开配置、严格加载方法和输入预处理说明。用固定输入比较导出前后所需输出；记录相等或使用的合理容差。无需为打包重新跑完整精度评测。
- 分清模型权重、特征缓存、分类统计和分类层；说明载入后能运行哪条评价流程。

## 上传与匿名发布

- 先完成包内容和最小运行验证，再上传。用户已明确授权创建并上传匿名仓库时，继续完成授权范围内的常规步骤；Skill 本身不扩大授权，也不额外制造重复审批。
- 默认从干净发布目录建立私有源仓库，只提交选定文件，不携带原项目历史。新仓库使用匿名提交身份且仅配置当前仓库，不更改全局 Git 身份。已有发布仓库先确认工作区与远端状态，保留无关改动。
- 使用用户选定的匿名平台；未指定时可考虑 Anonymous GitHub。先确认当前平台能力，浏览器控件随当前页面识别，不记录固定元素编号。该平台的非显然细节见 [平台操作注意事项](references/anonymous-github.md)。
- 只授权平台读取本次发布仓库，不扩大到其他私人资料。登录需要用户接管时保留页面，不在聊天中收集密码或验证码。
- 默认固定审稿版本而非自动追随研究分支。记录有效期和到期行为，优先到期停止访问，避免自动跳转个人源仓库。报告当前设置，不承诺永久可用。

## 验证真正交付的内容

- 从未登录状态打开实际审稿链接，确认文件可见、内部链接留在匿名站点，且不显示作者账号。登录用户自己的导航栏不等于公开页面泄露，需用未登录视图判断。
- 从匿名站点的实际下载入口取得压缩包，核对文件清单并检查个人信息；若包含二进制权重，比较公开下载文件与本地发布文件是否一致。不要仅验证本地包就宣称公开下载可靠。
- 核验与改动相称的运行路径，例如核心不变量、模型加载及入口执行。结构检查不能写成复现全部论文指标。
- 记录审稿 URL、源版本、范围、验证结果、有效期和更新方式。正文只给审稿链接；私有源地址留作项目维护。
- 更新发布时只提交本次范围，明确更新匿名快照后再验证受影响文件。不强推、不重建不相关仓库；登录或服务阻塞时保留已完成工作并说明卡在哪一步。

交付用简短中文说明匿名链接、包含内容、可复现范围和到期时间。无需向用户展开操作日志。
