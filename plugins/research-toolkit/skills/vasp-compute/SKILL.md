# VASP 计算与优化

先确定用户需要参数解释、输入准备、故障处理、执行计算还是性能优化。常规计算先采用适用的已验证配方完成目标；没有适用证据时建立稳定基线，不默认开展算法或吞吐筛选。解释一个参数不要求跑基准。下面的运行与短测建议仅用于已授权的执行或优化；只要求检查、方案或技能维护时不启动计算。已有授权和可信且未受本次改动影响的验证可复用，不逐项重复确认。沿用项目已有 VASP 接口和工作流，不因使用本技能迁移框架。

用户提供服务器、结构和计算目标后，由代理主动检查环境、查阅必要依据并提出可执行的输入和运行方案；不要求用户先懂参数、选优化方向或提供历史结论。研究目标和性能对照使用相关实际结构，不机械区分小、大体系或另造小模型。教学或功能验证可采用足以回答当前问题的简化模型，说明与目标体系的组成、覆盖度、环境和精度差异；其数值不替代目标体系结果。

涉及分子动力学时先检查当前运行脚本、模型文件及元数据，确认流程框架、势函数架构与MD引擎；不要从历史MACE实验或用户口头简称猜测模型。DP-GEN2是主动学习流程，不等于DeepMD描述符DPA-2。DeepMD/LAMMPS任务读取 [DeepMD长程模拟](references/deepmd-md.md)。需要迁移到新服务器、选择单条/吞吐/折中方案或检验技能实际行为时，读取 [MD应用与配置选择](references/md-application.md)。用户要求深入算法、不同执行策略或接近性能上限的探索时，再读取 [MD推理策略研究](references/md-inference-research.md)，不要把一次局部加速当成整个探索目标完成。先确定力的来源：VASP 在线计算力属于 AIMD，MACE/自有机器学习势或经典势驱动属于势函数 MD。后者读取 [势函数 MD 与优化](references/mlip-md.md)，复用已注册的 MD 工具或 ASE/其他成熟引擎；不要把 VASP 输入参数或 DFT 的 MPS 收益直接移植到 MLMD。

## 输入与科学目标

- 读取相关结构和项目配方，明确目标量、周期方向、金属/绝缘体、自旋、表面真空与约束。缺少会改变计算含义的信息时说明假设或询问，不能凭元素组成保证唯一正确配方。
- 协同核对 POSCAR、POTCAR、KPOINTS 与 INCAR。POTCAR 记录势版本、元素顺序与选择，使用用户合法已有文件，不在公开技能中附带势文件。
- 复用既定泛函、赝势、能量定义、应力需求及标签协议。推荐值要说明用途和适用条件；没有已有收敛依据时标为起点，不声称任何体系都足够。
- 将改变目标或数值近似的建议（如 k 点、ENCUT、LREAL、展宽、自旋、U、收敛阈值）与执行层改动分开报告。用户允许调整时仍记录变化，避免混成同一标签配方。
- 需要具体参数、优化或故障依据时，按需读取 [决策与来源](references/decisions.md)。调研新的加速机制或组合时读取 [组合优化](references/combinations.md)。不把整份文档当成每次必须执行的检查表。
- 准备可运行输入或处理未收敛任务时读取 [输入准备与恢复](references/input-and-recovery.md)，使用现有 ASE/pymatgen/项目接口产生文件，并检查实际写出的内容。把尚缺的势文件或收敛依据明确留作缺项，不用占位文件伪装可运行输入。

## 执行与优化

1. 主动检查程序变体、MPI/OpenMP、数学库、GPU、CPU绑定和现有入口，给出INCAR及执行配置的基础建议。已有合适工具就复用；缺少必要软件时，在任务授权内安装并验证，优先使用隔离环境。VASP及势文件使用用户已有授权来源，不把缺少普通依赖当成只能给方案的理由。核对实际安装版本支持什么。
2. 有相近可信记录就用于选择起点，没有也正常建立基线。需要优化大量独立DFT任务的吞吐时，优先考虑单卡多任务与MPS，再按实际显存、CPU预算和开销调整；不预设并发越多越好。性能筛选用实际结构的少量限步短测，看到足以选择或淘汰方案的规律即可停止，不要求每个候选完整收敛。
3. Gamma 专用程序只用于实际单 Γ 点且功能兼容的输入；Gamma-centered 多点网格不等于 Gamma-only。保持单次计算内 MPI rank/GPU 约束与多个独立计算共享一张卡这两层概念分开。
4. 电子求解算法与初始状态分别选择并说明依据。没有适用的已验证配方时，通常以 `ALGO=Normal` 建立基线；缺少兼容重启文件时配合 `ISTART=0, ICHARG=2` 冷启动。已有兼容状态时判断如何复用，Normal 也可热启动；Fast 不代表状态复用或必然提速。仅在需要加速且算法适用时，按[组合优化](references/combinations.md)在相同结构、精度和初猜下限步比较 Fast，确认收敛走势及所需结果后再用于后续任务；明显恶化的候选及时停止。适用的既有 Fast 验证可复用，不强制重跑 Normal。原生弛豫/AIMD 已在进程内延续电子状态，不另建逐电子步重启流程。MPS、线程、NSIM与这些候选按实测组合，分别测得的收益不能直接相乘。
5. 用户要求探索新优化时，根据当前热点主动检索维护者代码、HPC 案例和官方实现，形成“观察到的损失 → 候选机制 → 兼容性与代价 → 最小对照 → 保留条件”。先推进最有希望的一项，再根据实测保留组合或转向下一项。一个候选无收益不代表用户的吞吐探索目标已完成；达到约定的工作负载、组合验证与交付范围后收尾，不无限扩展搜索。不能只复述案例列表，也不以必须发现新技术为目标。已有工具适合时复用，尚无运行资源时交付具体输入/方案和缺失条件，不把调研标成已验证收益。
6. 用户授权运行时保留任务身份与官方收集路径。发生错误时区分程序环境、资源不足和电子自洽问题；只采用适用的错误处理器。改变输入的恢复记录为新尝试，不能隐去改动或无限重试同一错误。

对照至少固定输入/势、所需精度、目标量和任务集合，并记录实际NBANDS、电子迭代数及共载。不在输入文件相同但程序实际扩展了能带数时声称工作量完全一致。不根据用户提到某种加速就预设它有效；官方指南也不是穷尽式答案，社区案例是候选证据，不是已证实的新发现。

短测比较阶段耗时、残差变化、资源占用与争用，不能把未收敛结果计为可用DFT结构。仅当短测不足以判断最终收益或结果质量时，补必要的完整计算，可结合首批实际任务完成；不默认重跑完整四格。空闲且获准的多张GPU可并行筛选，各卡保留自身基线和资源记录，避免把硬件或共载差异当成配置收益。

从原始 OUTCAR 快速提取规模与计时可用 [inspect_outcar.py](scripts/inspect_outcar.py)。它只提供诊断事实，不判定训练标签合格；能量/力/应力仍用项目解析器、ASE 或 pymatgen 核验。LOOP、LOOP+ 与内部阶段存在嵌套，不能相加成总耗时；总时间减 LOOP 也不能直接归因于 I/O。

## 交付

参数建议：给出建议、理由、影响与尚未确认之处。
优化方案：给出当前任务可使用的输入/启动方式、线程与并发/MPS设置、选择依据和适用范围，标明短测筛选与完整验证分别支持什么；达到任务所需判断后交付，不为了补齐实验表继续扫描。
执行结果：区分已提交、进程退出、SCF状态、标签可解析及已收集；计算是否进入训练由上层项目决定。
性能结果：批量任务以相同结构集、相同 GPU/物理 CPU 配额下，合格且已回收的结构数/整批墙钟为主指标。报告单任务时间用于解释瓶颈，并保留显存峰值、CPU成本和结果差异。采样峰值标明采样，短批次折算不写成长期观测。
需要统一批次统计时可使用 [summarize_benchmark.py](scripts/summarize_benchmark.py)，输入格式见 [组合优化](references/combinations.md)。它只读取记录，不启动计算；缺少回收证据时不会把计算完成当成已收集。
本技能提供操作方法，不是后台执行器；没有真实调用与产物时不能报告已经运行。
