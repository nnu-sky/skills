# 组合优化：从机制到实际完成量

调研日期：2026-09-13。以下是候选方向，不代表所有项目已经测试。复用最新已验证配置，从当前主要损失选择少量有依据的组合；不机械执行全部条目，不更改正在运行任务的输入。

历史案例提炼的定性教训参见 [案例与适用边界](measured-cases.md)。原始实测证据由维护者私有保存，本分发不是可独立核验的 benchmark；案例用于判断是否值得复核，不作为其他体系的默认配置。

## 默认从实际结构短测开始

直接使用用户的实际结构与目标配方；不为性能筛选缩小晶胞、删除原子或降低截断能/k点精度。可限制电子步数形成短窗口，先看初始化、实际能带数、显存、阶段耗时和电子残差走势。窗口应覆盖所比较机制实际生效的阶段：例如Fast前段可能仍执行Davidson，初始化也可能主导最初几步；不能仅凭最初几步排序，也不固定要求所有任务跑同一个步数才算有效。

本节用于性能筛选，常规计算不要求逐项比较这些候选。需要优化大量独立任务吞吐时，先比较合理单任务基线与单卡多任务/MPS，再选择有瓶颈依据的线程、NSIM或电子初猜组合。只保留少数有希望的候选继续观察；明显无效、资源不足或残差恶化的候选可以在未收敛时淘汰。短测得到的是筛选结论，不是最终能量/力标签，也不能直接用限步耗时折算已完成结构/小时。

### Normal/Fast与状态复用的基础候选

先复用适用的已验证配方；缺少证据时通常以 Normal 建立基线，再按实际加速需求选择少量候选，不要求全部运行。ALGO与初猜是两个独立维度；Fast可能有利，Normal配合合适参考也可能更好，均不作为必然收益。

| 可用条件 | 可选起点 | 主要判断 |
|---|---|---|
| 没有兼容参考状态 | `ALGO=Normal, ISTART=0, ICHARG=2` | 建立当前结构的冷启动基线，无需先计算一个参考 |
| 已有冷启动基线、任务支持Fast且需要加速 | 在相同冷启动下限步比较`ALGO=Fast` | 先筛选求解阶段和残差走势；保留时确认所需结果与收敛总耗时，不能只看单步更快 |
| 已有兼容、收敛的相近结构CHGCAR | `ALGO=Normal, ISTART=0, ICHARG=1` | 读取电荷初猜，观察是否减少求解工作；此前局部案例支持优先尝试 |
| 已有电荷复用基线、Fast适用且需要加速 | 同一CHGCAR下限步比较`ALGO=Fast` | 组合可能更快，也可能降低最终力的一致性；短测无法确认时才补必要完整对照 |
| 已有兼容WAVECAR、固定晶胞单点 | 可从`ISTART=1, ICHARG=0`配合Normal起步，按需比较Fast | 先确认实际读入成功；晶胞变化或其他续算类型按ISTART语义另选，不能把波函数复用认定为总比电荷复用好 |

核对结构/原子顺序、势、电子数、自旋、k点及实际文件兼容性；不兼容则正常冷启动。人为生成新参考只有在预期多项复用能摊销成本时才考虑，不是运行前置条件。不要在每个电子步之间导出、重启或调度历史状态；同次SCF内部状态由VASP自行延续。依据：[ALGO](https://vasp.at/wiki/ALGO)、[ISTART](https://vasp.at/wiki/ISTART)、[ICHARG](https://vasp.at/wiki/ICHARG)。

### 多张空闲GPU并行筛选

在已获准且现场核对为空闲的卡上可同时运行不同对照，各自使用明确CPU配额及任务目录。每张卡建立或复用可信的本卡基线，比较候选相对本卡基线的变化；不要直接用“GPU A跑Normal、GPU B跑Fast”的绝对耗时判定算法胜负。不同型号/构建分别形成建议；同型号但差别接近波动时，才交换配置或在同卡补一个必要对照。卡之间共享CPU域时合并核预算，不能逐卡重复分配。并行筛选节省实验历时，不等于已经验证同卡组合，最终使用的组合仍需实际短测。

## 优先候选

| 组合 | 可能的收益机制 | 适用条件与最小对照 |
|---|---|---|
| Γ专用程序 × NSIM × 同卡并发/MPS | 单任务开销与资源占用改变后，最佳并发可能变化 | Γ-only且功能兼容；比较最终组合的同批完成时间与显存，不能将分别测得的倍率相乘 |
| OpenMP × FFT计划复用/数学库 × NUMA | CPU计算更快，但FFT准备、线程启动和跨NUMA开销可能抵消收益 | 查编译与实际动态库；非MKL FFT路径核对fftlib，少量物理核对照后才考虑SMT |
| NSIM × 实际NBANDS × 电子算法 | 分块、能带填充和迭代路径共同决定时间 | 从OUTCAR读实际能带数；改变并行度可能自动增加NBANDS，勿为提速删除科学上需要的空带 |
| 相近结构 × WAVECAR/CHGCAR初猜 × 输出策略 | 减少SCF迭代，可能比单步加速更有价值 | 元素、势、自旋与输入兼容；先短测冷/热启动走势，计入文件读取；最终收益或质量不明时补必要完整计算 |
| 连续相关结构 × 交互式VASP × 外部优化/采样 | 复用进程内电子态，减少重复初始化及重启文件I/O | 固定成分和兼容晶胞/功能；优先复用 vasp-interactive，比较同一结构序列的整段时间、每帧结果及退出/恢复行为 |
| SCF震荡 × 混合参数/空带 × 电子算法 | 减少无效迭代或失败重试 | OSZICAR/OUTCAR显示残差或占据问题；短测筛选有改善的候选，恢复完成时核对完整SCF及力、应力和电子态 |
| 小任务分组 × CPU或GPU路线 × 减少初始化损失 | 极小任务可能受GPU传输/启动开销主导 | 只在初始化或延迟占比高时比较一批CPU/GPU任务；不因已有GPU而默认GPU必胜 |
| 本地临时盘 × 必要输出 × 原队列回传 | 减少大量小文件和不需要的大文件I/O | 日志表明I/O占比高；保留恢复/后处理需要的文件，验证回传失败可重传而不重算 |
| 杂化泛函 × Davidson/ACE × 已支持的构建 | 减少重复Fock算符应用 | 仅对杂化泛函相关任务；核对版本、编译条件与是否已默认启用，不能把默认功能算成新改进 |
| 多GPU通信 × NCCL/拓扑 × 工作分配 | 降低跨卡等待和不均衡 | 仅当单任务确有多GPU工作；独立单GPU批次不套用多节点网络开关 |

官方明确指出非MKL的OpenMP FFT需注意fftlib，否则高线程数的计划开销可能很大：[OpenMP/FFT配套](https://vasp.at/wiki/Combining_MPI_and_OpenMP)。不要只把OMP数值调大。

关于NBANDS的并行填充：[NBANDS](https://vasp.at/wiki/NBANDS)。关于Γ程序与小任务路线，NERSC还指出大量小任务可能因CPU/GPU传输延迟而更适合CPU节点：[NERSC实践](https://docs.nersc.gov/applications/vasp/)。该中心的核心数、绑定命令和库版本不是任意实验室机器的默认配置。

相关输入小变化时可以复用电荷初猜：[ICHARG](https://vasp.at/wiki/ICHARG)、[ISTART](https://vasp.at/wiki/ISTART)。必须仍做目标所需的自洽计算，不能用ICHARG=11等固定电荷方式替代训练标签的SCF。DFT+U需注意LMAXMIX/电荷表示，磁性或多稳态体系需检查电子态；不同构型并非按化学式相同就能复用波函数。初猜可改变收敛到的解，不能只检查能量/原子。

ALGO=Normal/Fast/VeryFast 选择电子求解算法；ISTART/ICHARG 与重启文件选择初始状态，两者是独立维度。Normal 可以热启动，Fast 不代表自动复用上次结果。比较文件重启与常驻进程时，两边都应采用合理的状态复用基线，而非把冷启动与热启动的收益全归于进程复用。

用户不了解这些参数时，由代理根据目标给出建议并解释验证证据，不要求用户先选择术语。ISTART=0不读取历史WAVECAR；ICHARG=2以原子电荷密度叠加初始化，再继续自洽。ICHARG=1读取CHGCAR作为初猜；加10（如11/12）则固定电荷用于非自洽场景，不能为了加速把它代入需要完整自洽的新力标签。参见[ISTART](https://vasp.at/wiki/ISTART)、[ICHARG](https://vasp.at/wiki/ICHARG)。

Fast可能降低每步成本，也可能收敛更差或使力/应力偏离。先在相同初始化下短测；需要确认最终收益和目标量时，再让保留候选完成SCF，有可疑差异才用更严格Normal参考判断。既定配方下的结果一致性不等于已验证泛函、k点、截断能或电子态选择本身；一次构型通过也不支持跨体系默认替换。[ALGO可靠性边界](https://vasp.at/wiki/ALGO)

能量/力/应力通过也不能证明未占据能带已同等收敛。若目标包含能带、DOS、光学或其他空态相关性质，另检查所需轨道与能带数、残差及对应收敛设置；不能复用只为力标签验证的Fast建议。RMM-DIIS的初始轨道与空态处理需按[官方算法说明](https://vasp.at/wiki/RMM-DIIS)及[IALGO适用条件](https://vasp.at/wiki/IALGO)判断，不将ICHARG=12的算法诊断用法混入完整自洽标签流程。

### 连续结构与交互式接口

[VASP 的 IBRION 文档](https://vasp.at/wiki/IBRION)列出 stdin 交互与 Python 插件两条入口；所装版本、编译选项和晶胞输入格式必须核对。[vasp-interactive原仓库](https://github.com/ulissigroup/vasp-interactive)提供 ASE 接口，依赖 ASE、psutil，LGPL-2.1；但其 README 已声明冻结，并指向[tiangroup-uofa维护分支](https://github.com/tiangroup-uofa/vasp-interactive)。2026-09-13 原仓库的 GitHub archived 字段仍为 false，这不代表仍受积极维护。采用时核对继任分支、依赖和具体 commit；当前构建兼容性另行实测。

先用已有二进制运行维护者的兼容性测试，再考虑接入。历史实现可能输出缓冲或截断，晶胞变化能力取决于版本/补丁；输入等待期间 MPI 也可能占用 CPU。独立不相关候选、成分变化或需要长时间等待的流程未必适合常驻计算器。原生 AIMD/弛豫本已复用内部状态，不能把“每帧重新启动VASP”的劣化基线当作它们的正常基线。

接口版本可能强制ISIF等参数，不能只传入期望值后忽略库的覆盖；检查实际生成的INCAR，并使对照的目标量和实际设置一致。固定给定晶胞/坐标的交互单点并不等于运行晶胞弛豫，但与原科学配方的差异仍需明确记录。

最小对照可选择已有参考A和少量相关结构：以当前合理的文件重启流程对比交互流程，包含初始化、计算、退出及文件写出全过程；检查每帧所需标签、停止时的额外步、进程清理和逐帧身份。[历史案例教训](measured-cases.md)是：接口可用不等于端到端加速，短序列尤其需要计入退出成本。不引用维护者加速倍率作为本项目收益，也不为一个测试修改共享VASP源码或移植整个工作流。

若原队列是一项任务对应一个结构，交互式输出需要逐帧对应原任务身份，并排除停止协议产生的额外步；未经这一映射验证，不把整个多步OUTCAR直接当作一个原候选的标签交给训练。

### 从慢的原因选择候选

读取 `inspect_outcar.py` 输出和对应的 CPU/GPU 原始采样：SETDIJ 等内部阶段占比高时考察线程/库；电子迭代数异常时先查混合/结构/占据；初始化明显时考虑小任务分组或连续交互；多卡工作有通信等待证据时才调整通信。OUTCAR计时不能代替传输日志或GPU时间线，不能由低GPU利用率直接断定PCIe瓶颈。

[EPCC 2026 VASP工作坊基准](https://github.com/aturner-epcc/2026-01_vasp-performance)提供跨系统实测输入和结果，适合检查自己的负载是否与公开基准可比（GPL-3.0，2026-03-26推送）；不直接复用其硬件倍率。[电子收敛诊断](https://vasp.at/wiki/Troubleshooting_electronic_convergence)提供混合/算法候选的依据。两者是提出下一项对照的资源，不是新增依赖或全量扫描要求。

杂化泛函参考：[LFOCKACE](https://vasp.at/wiki/LFOCKACE)、[ALGO](https://vasp.at/wiki/ALGO)。ALGO=VeryFast不支持杂化泛函；Normal与ACE的配合需查实际版本。用户只算普通GGA时跳过该方向，不为使用优化而更换泛函。

## 有依据时再深入

- 实际并发与准入门槛：配置中的max_tasks只给出上限，不证明这些槽位真的被使用。结合实时等待原因、启动期峰值、现有任务占用和CPU锁判断容量。某类小任务的已测显存范围可能支持更密集派发，但不能把它当作大晶胞、不同实际NBANDS/FFT网格/NSIM/算法的全局门槛；先用同批3/4等相邻并发验证整体吞吐，再讨论按任务规模配置。
- MPS资源份额与上下文内存：使用率上限可能减小上下文开销，也可能降低计算吞吐。查[对应驱动MPS文档](https://docs.nvidia.com/deploy/mps/when-to-use-mps.html)，以同卡批次比较，不把份额误认为隔离预留。
- 共享GPU采样的 memory.used 是整卡占用，可能包括其他任务与MPS服务。记录共载及可得的客户端信息，不能把整卡峰值称为单任务显存，也不能将服务占用与客户占用盲目相加。获取不到可靠归属时保留整卡测量口径。
- Nsight Systems时间线区分CPU等待、GPU运算、拷贝与同步；必要时再看Nsight Compute/roofline。使用[Roofline方法](https://docs.nersc.gov/tools/performance/roofline/)需要实测计数，不能从FP64规格或GPU利用率推出瓶颈。分析器开销窗口不参与吞吐对照。
- 功耗/频率只在目标含能效、出现节流或硬件约束时分析，不常规修改整机时钟。记录能量/已收集任务及执行时间；最高频率不必然是成本最优点。
- 若库或算法实现确有重复拷贝、重复准备等证据，可检查源码并做隔离实现；需有VASP源码访问权。不是每次都修改求解器，也不声称未实现的“常驻VASP服务”可以无成本复用上下文。
- 重复数学量的缓存：先证明被复用的量只依赖哪些输入及初始化状态，缓存键覆盖这些依赖；多线程下核对状态隔离及形状切换。用原实现核对局部完整输出，再比较完整DFT。函数微基准即使快几十倍，也可能只节省整个任务几秒；只有总时间收益超过邻近基线漂移才值得保留额外实现。受限VASP源码与补丁留在用户私有环境，公共技能只保留独立方法及经授权公开的证据。
- CPU标量热点与SIMD：VASP维护者的[OpenMP与SIMD研究](https://doi.org/10.1002/qua.25851)提供GGA批量向量化的实现方向。先用函数采样确认热点，再核对当前调用链、SIMD宽度、编译器和线程安全；源码中存在向量函数不代表当前构建已使用它。论文的特定平台局部收益不能写成当前GPU版本的整体收益，仅添加宏也不保证原标量调用会自动替换。
- 复用SIMD模板时核对目标泛函分支是否完整，以及屏蔽点内部算术是否安全。有效输出接近不代表未触发除零；对尾部、密度截断和线程局部状态做有针对性的数值检查。只在适用分支启用候选，其他输入保留原路径。
- CPU预算同时记录实际CPU秒和物理核数乘墙钟。增加物理核与开启SMT是不同试验；多GPU可能共用一个NUMA核池，不能逐卡重复计算容量。核租约已满也不等于硬件持续满负荷。单任务CPU加速后，若并发电子求解等待增加，先看相邻返回控制与阶段计时；不能把单任务收益与MPS收益相乘。错峰启动是可检验的候选，其等待应计入整批时间。

## 公平对照与停止条件

默认目标是单位时间完成的可用DFT结构数量；用户另有延迟或成本目标时按其目标判断。选择实际结构或少量代表输入，不机械分小、大体系。只有负载跨度可能改变并发容量、热点或算法适用性时，才补另一代表输入的短测。记录科学配方、构建、实际参数与共载；仅在差别接近波动且影响选择时补相邻或交换对照，不默认完整四格、多种子或大范围搜索。

保留条件由项目精度和目标决定。短测已足够排除候选或确定执行起点时就停止筛选。若单步变快但迭代走势不同、参考态可能改变电子解、最终力/应力尚无可用依据，或初始化/收尾/回收可能改变排名，只对保留候选补必要完整SCF或首批实际任务。若单任务变快但并发下降，判断整批完成量。微小差别接近噪声时记“无明确收益”，不能自动选更复杂配置。已有相容结果可复用，不为每次调用重复做质量对照；历史完整实验用于积累技能证据，不是日常执行的必经流程。

同 CPU 配额比较线程与并发时，让两条路线完成同一结构集；例如8物理核下比较四结构按2任务×4核分两批与4任务×2核一批的全部时间。不能只凭单项使用更多核后更快来选整机方案。参考电荷已经存在时单列已付成本；为本批新建参考则计入生成、保存和复制成本，不强迫独立候选串行等待参考。

将固定输入列表、同时执行的槽位数和逐任务回收记录分开。调整并发不应静默改变任务数量或只复制同一个输入来替换既定结构集；重复同一结构可以用于机制对照，但要标明重复负载，不能把运行次数当成新增独立训练样本数。

用户接受小误差以研究趋势时，同时核对相关结构的能量差、排序和关注的力变化。单结构最大力误差通过不保证两结构力差也通过；近简并能量差需要直接比较该差值与误差，不能用平均每原子能量误差掩盖。报告实际连续误差与适用范围，不把某次5 meV/Å筛选写成普遍标准。

诊断 MPS 时先核对安装版 Nsight 的软件 CUDA 跟踪能力（如 `cuda-sw`），并把客户端 PID 与核函数记录对应。分析 GPU 区间并集、拷贝、启动 API 和 GPU 空档中的 CPU 热点；核函数生命周期重叠不等于测得 SM 同时执行，API 返回到 GPU 开始的间隔也含流依赖。CPU/GPU/同步时间有重叠，不能相加分摊整批墙钟。若分析器线程卡住而普通对照正常，保留失效 trace、缩小采样范围重试一次；该超时不作为普通 MPS 性能。

一次批次测得的DFT/小时是折算吞吐，不是全天观测。回传时间必须与宣称的测量范围一致。电子未收敛、结果未解析和未收集是不同状态；不要新增项目未要求的科学筛选门槛。

## 批次记录工具

`python scripts/inspect_outcar.py /path/to/OUTCAR [other/OUTCAR ...]` 从显式指定的原始文件输出实际规模、SCF步计数和各类计时。未结束文件保留缺项；拼接多个运行的文件拒绝合计。完整电子/离子收敛、能量/力/应力和回收仍由现有解析器与工作流核对。

`python scripts/summarize_benchmark.py batch.json` 输出JSON，不执行任务。每个输入文件只描述一个批次；将两种配置分别运行后，由Agent在相同负载与精度下比较。最小记录示例：
