# 把技能用于一台新服务器

这是实际应用流程，不要求用户已有优化结论。输入至少要能找到结构、势函数、计算目标和获准资源；缺少其中会改变物理含义的内容才追问。已有项目先读取其当前运行索引及直接相关证据，用本机最好的已验证兼容入口作为基线。

## 环境与入口

核对物理GPU UUID、进程/资源用途、CPU/NUMA、驱动与候选环境。低利用率不等于无人使用；MPS服务需进一步查客户端。临时保留卡、CPU租约、CUDA_VISIBLE_DEVICES、查询和锁必须指向同一物理设备。已有真实计算占用时，不用共载短测给出独占性能排名。

从项目已有入口追踪实际导入和安装顺序，找到所需模型、结构、Python环境、CUDA/C++扩展与辅助模块。定制入口在别的机器上可能需要迁移；复用已有依赖清单/脚本，只补缺失项，避免复制整台机器或把私人绝对路径写进通用Skill。没有对应定制实现时使用兼容的成熟入口，并明确比较范围。

区分可复用执行接口与实验包装器：消融包装器可能额外要求某次基线文件，而直接安装接口没有这个依赖。读取对应接口说明后选择真实入口，不伪造参考文件；独立能量/力验证仍须保留。

冻结模型若在裸加载时提示未知自定义算子，先按所用DeepMD版本的正常加载流程注册扩展（PyTorch入口可能需要先导入 `deepmd.pt.cxx_op`），不要立即误判模型损坏或重导出权重。

首次小任务应能证明：模型类型正确、所选算子真实调用、能量力检查有效、GPU/CPU绑定一致、输出可读取。遇到编译失败先区分工具链/头文件/不支持架构/内核配置；不能把装包成功当运行成功。首次编译时间与缓存后启动分开记。

## 按目标做少量筛选

已授权优化且需要配置比较时，先测或复用当前单条基线；再按实际任务数量比较少量批量与多进程/MPS配置。用显存、CPU成本及单条速度决定下一点，不预设最大批次，也不追求把显存填满。若大批次总量高但每条太慢，可试拆成几个小批次；只有实际共享GPU的进程才需要验证MPS客户端。

CPU核/线程只选能检验当前瓶颈的少量配置；所有计算库在租约/线程设置后导入。不同服务器分别复核；保留某台机器的旧兼容入口，不代表其他新路径已被否定。

记录每个方案的模型/精度/时间步/输出、批次与进程数、物理核及线程、MPS状态、总墙钟、每条速度、总吞吐、显存、准备时间及质量结果。多进程用整组首开始至末完成，保留最慢/最快worker速度，不能只乘一个幸运worker的值。

MPS方案还应核对自建服务的CPU亲和性与成本，避免只数worker而遗漏服务；服务CPU时间若与worker计量窗口不同要注明。不修改他人服务的绑定。

混合历史端点与新测配置时，各记录保留来源、日期及是否重测，不把跨窗口排名称为同时配对增益。选择器的valid由调用者依据真实检查给出，不能由速度好坏决定。

需要比较延迟与吞吐时给出以下选择；用户只指定其中一种目标时，交付该目标所需结果即可：

- 单条最快：已测每条速度最大者，明确是平均值还是最慢worker。
- 单卡吞吐最高：已测合计速度最大且质量通过者。
- 折中：在用户接受的单条降速内取总量最高者。用户没给阈值时列出少量Pareto取舍点，说明牺牲多少单条速度换多少吞吐；不称某个主观阈值为唯一最佳。

可用 `scripts/select_md_configs.py` 汇总一组同服务器、同任务、可比资源的测量。输入JSON示例仅说明字段，不是性能建议：

```json
{"comparison":{"server":"target","workload":"actual-model-and-structure"},"records":[{"id":"one","trajectories":1,"aggregate_ns_h":4.0,"valid":true},{"id":"two","trajectories":2,"aggregate_ns_h":7.0,"valid":true}]}
```

用当前Python执行 `select_md_configs.py results.json`，输出两种极值和Pareto点；只有阈值已明确时才加 `--min-speed-fraction 0.75` 等参数。该工具只做选择，不判断输入是否公平、不替代能量力验收；平均每条速度也不代表最慢worker。

## 验收与反馈

短测筛出候选后，仅给有希望或难以判断的方案补稍长确认和必要独立数值检查。核对实际执行图/服务/客户端，不凭开关名认定启用。数学近似与工程误差分开；用户拒绝的近似不再作为候选。目标范围之外的模型、virial、边界与长期物理量明确待验证。

本次服务器交付包含可复现命令或配置文件、输入定位、依赖、与目标相关的选择、原始结果位置、误差及限制。参数与机器路径放项目配置，Skill保持判断方法。释放自己的任务/服务/锁，恢复临时设备限制；正式任务和收集器是否采用另行说明。

验证Skill时给代理真实请求、Skill及最少原始输入，不预先告诉它推荐参数。检查它是否主动找到兼容入口、识别资源、做有区分力的实验、解释取舍并收尾；根据真实失败修正文档。没有空闲卡时可以完成环境/兼容检查，但不能把这写成吞吐方案已经测定。
